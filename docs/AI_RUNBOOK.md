# AI 新窗口推进手册

本手册给每个新 AI 窗口使用。目标不是重新解释项目，而是保证任何窗口都能从仓库状态恢复上下文，按票继续推进。

## 一句话原则

仓库文件是事实源，聊天记录只是辅助。新窗口必须从 `AGENTS.md` 和本手册重建上下文。

## 可复制启动提示词

```text
请先读取 AGENTS.md 和 docs/AI_RUNBOOK.md，并严格按其中的新窗口续跑协议工作。

本项目设计已冻结：不要重新设计，不要引入新顶层概念，不要做票范围外的事。
请按顺序读取 SPEC.md、docs/tickets/QUEUE.md、当前票全文、docs/DATA_MODEL.md。
然后检查 git status --short，说明当前票状态、禁区、验收命令和你的第一步。

如果已有 In Progress 票，只续做那张票。
如果没有 In Progress 票，请按 QUEUE 的下一张票认领。
完成的定义是：当前票验收 + SPEC §6 基线全部真实跑过，并把输出写入票尾。
```

## 新窗口接手清单

- 读 `AGENTS.md` 和本手册。
- 读 `SPEC.md`，确认铁律、禁区、验收基线。
- 读 `docs/tickets/QUEUE.md`，确认唯一可推进票。
- 读当前票全文，摘出范围、禁区、验收和回滚要求。
- 读 `docs/DATA_MODEL.md`，只查当前票需要的表、公式和参数。
- 运行 `git status --short`，分清已有改动与本窗口改动。
- 开工前向用户简短说明：当前票、修改面、测试门、风险点。

## 单票执行循环

1. **认领**
   把 QUEUE 中当前票标为 In Progress，并确保没有第二张票同时 In Progress。

2. **锁范围**
   在当前票尾记录「本轮范围」。票外发现的问题只写入 QUEUE 的 Backlog。

3. **先测后改**
   对公式、迁移、CLI 行为和降级路径优先写测试。窄改动可以小步实现，但不能跳过最终自动化验收。

4. **实现**
   按当前票和 `DATA_MODEL.md` 写代码。任何常数必须走 config 参数登记处；任何冻结仓库只读参考，不修改。

5. **验证**
   至少运行：

   ```powershell
   cargo fmt --check
   cargo clippy --workspace --all-targets -- -D warnings
   cargo test --workspace
   ```

   还要运行当前票列出的额外集成命令。

6. **交付**
   在当前票尾填写变更清单、验收输出、阻塞与裁决记录、技术选择说明、回滚方式。

7. **等待确认**
   票完成后等用户确认再 commit。commit message 用中文，不 push。

## 交接记录模板

把这段写到当前票尾，供下一个窗口继续：

```markdown
## AI 交接记录（YYYY-MM-DD HH:mm）

- 当前状态：
- 已完成：
- 未完成：
- 已跑验证：
- 未跑验证及原因：
- 阻塞点：
- 下一步建议：
```

## 防错规则

- 不凭记忆推进；每个窗口都从文件重建上下文。
- 不把「测试应该会过」写成「测试已通过」。
- 不回退用户或其他窗口留下的改动。
- 不在 P01 做 P02+ 的能力。
- 不把外部 AI 评分直接写入掌握度；引擎必须 evidence-bound 自己评分。
- 不在代码里写域特定逻辑；Domain Pack 只能声明。
- 不修改 `C:\MyProject\Polaris` 和 `C:\MyProject\Learned`。

## 卡住时怎么办

卡住不是失败，但必须可审计：

- 在当前票尾写明阻塞点。
- 给出 1 个推荐方案和理由。
- 标出该方案是否改变设计、验收或数据模型。
- 停下来请用户裁决；不要擅自改设计。
